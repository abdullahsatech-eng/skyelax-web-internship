# Architecture

Static site: HTML + CSS + classic `<script defer>` files sharing one `window.TaskFlow` namespace (Validation, Tasks, Storage, UI). No build step, and it also runs from `file://`.

## Modules
| File | Responsibility | Depends on |
|---|---|---|
| `js/validation.js` | Allowed values, form validation, stored-record validation, date check | - |
| `js/tasks.js` | Pure functions: create/update/delete/status, overdue, stats, search/filter/sort | - |
| `js/storage.js` | Load/save/reset, schema version, recovery and backup | validation |
| `js/ui.js` | All DOM rendering and form helpers (`textContent`, no `innerHTML`) | validation, tasks |
| `js/app.js` | State, event listeners (delegation), orchestration, persistence calls | all |

`tasks.js`, `validation.js` and `storage.js` have no DOM dependency, so the unit tests load them in Node with `vm` (`storage.js` accepts a store argument). Script order in `index.html` matters: validation, tasks, storage, ui, app. All dropdown options (form, filters, sort) are written in `index.html`, not generated by JS, so they exist even if a script fails.

## State (in `app.js`)
`tasks`, `searchQuery`, `filters {status, category, priority}`, `sortOption`, `editingTaskId`, plus two transient flags (`confirmingDeleteId`, `confirmingReset`). The DOM is re-rendered from this state; it is not the source of truth.

## Data flow
event -> handler in `app.js` -> validate (`validation.js`) -> pure change (`tasks.js`) -> new state -> `render()` -> `saveTasks()` -> feedback message.

## CSS
`base.css` tokens, reset, focus, utilities - `layout.css` page structure - `components.css` buttons/forms/cards/badges/feedback - `responsive.css` enhancements. Mobile-first.

## Responsive strategy
One layout, three breakpoints: ~600px (wider search field), ~1024px (form beside list), ~1600px (larger max width) plus a narrow-phone rule (~360px) and a short-landscape rule (`max-height: 40em`). Everything else is fluid: `min(100% - 2rem, 75rem)` container, `auto-fit/minmax()` grids, `clamp()` headings, `overflow-wrap: anywhere` for long text, 44px minimum control height. No device detection or device-specific CSS.

## Accessibility design
Landmarks (`header`, `main`, `footer`, labelled `section`s), skip link, `role="status"` live region for feedback, `aria-invalid` and `aria-describedby` on fields, focus moved to the first invalid field, focus restored after edit/delete/cancel, inline confirmation instead of a modal (no focus trap needed), Escape cancels confirmations and edit mode.
