# FixFlow API reference

Base URL (local): `http://localhost:4000/api/v1`. All bodies are JSON (`Content-Type: application/json`).
Timestamps are ISO 8601 strings in UTC. This document describes what the code in `server/src` implements.

## Service request object

| Field | Type | Rules |
|---|---|---|
| `id` | string | 24-character hex id generated by MongoDB. Read-only. |
| `title` | string | Required. Trimmed. 5 to 100 characters. |
| `description` | string | Required. Trimmed. 10 to 1000 characters. |
| `category` | string | Required. `it`, `maintenance`, `electrical`, `plumbing`, `other`. |
| `priority` | string | `low`, `medium`, `high`, `urgent`. Default `medium` on create. |
| `status` | string | `open`, `in-progress`, `resolved`, `closed`. Default `open` on create. |
| `requesterName` | string | Required. Trimmed. 2 to 80 characters. |
| `requesterEmail` | string | Required. Valid email, at most 254 characters, stored in lowercase. |
| `createdAt` | string | Set by the server on creation. Read-only. |
| `updatedAt` | string | Set by the server on every update. Read-only. |

Sending `id`, `createdAt`, `updatedAt` or any other unknown field in a `POST` or `PUT` body is rejected with `422`.

## Response formats

Single resource: `{ "data": { ...serviceRequest } }`

List: `{ "data": [ ...serviceRequest ], "meta": { "page", "limit", "total", "totalPages", "statusCounts" } }`

Error: `{ "error": { "code": "...", "message": "...", "details": [ { "field", "message" } ] } }`
(`details` appears only for validation errors.) `204` responses have no body.

## Endpoints

### GET /requests

Query parameters (all optional):

| Name | Rules | Default |
|---|---|---|
| `search` | up to 100 characters. Case-insensitive match in title, description or requester name | none |
| `status` | one of the status values | none |
| `priority` | one of the priority values | none |
| `category` | one of the category values | none |
| `page` | whole number, at least 1 | `1` |
| `limit` | whole number, 1 to 50 | `10` |

Results are newest first. `meta.total` is the number of matches; `meta.totalPages` is `ceil(total / limit)`
(`0` when nothing matches). `meta.statusCounts` counts **all** requests per status and ignores filters; the UI
uses it for the status summary. An empty result is `200` with `"data": []`. Unknown query parameters are ignored.

```
curl "http://localhost:4000/api/v1/requests?status=open&priority=high&page=1&limit=10"
```

```json
{
  "data": [
    {
      "id": "65f1c0a2b7d4e9a1c3f50a11",
      "title": "Projector will not turn on",
      "description": "The projector in meeting room B shows no signal.",
      "category": "it",
      "priority": "high",
      "status": "open",
      "requesterName": "Demo Requester",
      "requesterEmail": "demo.requester@example.com",
      "createdAt": "2026-01-05T09:00:00.000Z",
      "updatedAt": "2026-01-05T09:00:00.000Z"
    }
  ],
  "meta": { "page": 1, "limit": 10, "total": 1, "totalPages": 1,
            "statusCounts": { "open": 1, "in-progress": 0, "resolved": 0, "closed": 0 } }
}
```

(The id above is an illustrative value, not real output.)

### GET /requests/:id

`200` with `{ "data": {...} }`. `400 INVALID_ID` if `:id` is not 24 hex characters. `404 NOT_FOUND` if no such request.

### POST /requests

Body: `title`, `description`, `category`, `requesterName`, `requesterEmail` (required); `priority`, `status` (optional).
Returns `201` with the created resource and a `Location: /api/v1/requests/<id>` header.

```
curl -X POST http://localhost:4000/api/v1/requests -H "Content-Type: application/json" ^
  -d "{\"title\":\"Projector will not turn on\",\"description\":\"The projector in room B shows no signal.\",\"category\":\"it\",\"requesterName\":\"Demo Requester\",\"requesterEmail\":\"demo@example.com\"}"
```

(`^` continues a line in Windows cmd; use `\` on macOS/Linux. Postman is easier for JSON bodies.)

### PUT /requests/:id

**Semantics:** full replacement of the editable fields. Send all seven: `title`, `description`, `category`,
`priority`, `status`, `requesterName`, `requesterEmail`. A missing field is a `422`, not "keep the old value".
The server refreshes `updatedAt`; `id` and `createdAt` never change. Returns `200` with the updated resource,
`400 INVALID_ID`, `404 NOT_FOUND` or `422 VALIDATION_ERROR`.

### DELETE /requests/:id

`204 No Content` with no body when deleted. `400 INVALID_ID` or `404 NOT_FOUND` (including when it was already deleted).

### GET /health

`200` `{ "data": { "status": "ok", "database": "up", "uptimeSeconds": 42 } }` when the database answers a ping.
`503` `{ "error": { "code": "SERVICE_UNAVAILABLE", "message": "The API is running but the database is unavailable." } }`
otherwise. No connection details are ever included.

## Status codes

| Code | When |
|---|---|
| 200 | Successful read or update |
| 201 | Created |
| 204 | Deleted (no body) |
| 400 | Malformed JSON (`MALFORMED_JSON`), malformed id (`INVALID_ID`), other unreadable input (`BAD_REQUEST`) |
| 404 | Valid id with no record (`NOT_FOUND`) or unknown route (`ROUTE_NOT_FOUND`) |
| 413 | Body larger than 10 KB (`PAYLOAD_TOO_LARGE`) |
| 422 | Well-formed input that fails validation (`VALIDATION_ERROR`), including bad query values |
| 500 | Unexpected failure (`INTERNAL_ERROR`); details are logged on the server only |
| 503 | Database unavailable (`SERVICE_UNAVAILABLE`) |

`409 Conflict` is not used: no operation here has a genuine conflict case (emails and titles are not unique).
Unsupported methods on a known path (for example `PATCH /requests/:id`) return `404 ROUTE_NOT_FOUND`.

## Validation error example

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "The submitted data is not valid.",
    "details": [
      { "field": "title", "message": "Title must be at least 5 characters" },
      { "field": "category", "message": "Category must be one of: it, maintenance, electrical, plumbing, other" }
    ]
  }
}
```

Only the first problem per field is reported. Unknown fields are reported as
`{ "field": "id", "message": "Unsupported field(s): id" }`.
